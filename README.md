# masters

## Model structure

- Root Directory (masters)
  - Contains key scripts such as `main.py`, configuration files, logs (`masters.log`), and documentation (`README.md`).
  - `requirements.txt` lists dependencies for reproducibility.
 
- configs/
  - Supposed to be used to store configuration files for model training and processing; however, for this project, it remains empty. 

-	notebooks/
  -	Contains results_demo Jupyter notebook with visualizations of the query results, as well as serial versus parallel execution runtime tests

- data/
  - Manages input data for model training and use.
  - raw/:
    - Contains original images and its metadata (/images and /styles) in .jpg and .json formats, respectively. Summary metadata files (images.csv, styles.csv) are in this directory too.
  - query/:
    - Contains query images (female/, male/, unisex/) and corresponding responses with matches ids in the form of .json files (responses/).

- embeddings/
  - Stores precomputed embeddings of the database images (embeddings.json); can be generated by running setup_create_embeddings_from_db_images.py

- src/
  - Core implementation scripts, divided into functional submodules:
    - ConvNeXt_utilis/: Model initialization and descriptions.
    - feature_extraction/: Scripts for extracting feature vectors.
    - pinecone_client/: Functions for working with Pinecone, including index creation and vector upsertion, at this point not used.
    - preprocess/: Image preprocessing and embedding retrieval.
    - utilis/: General utility functions.
	
- tests/
  - Contains speed test script.

- setup_*.py scripts
-   Automate embedding creation and database indexing.

This hierarchical structure ensures efficient data handling, modular model development, and streamlined experimentation. Certain directories, such as, for example, src/pinecone_client and tests/ remain empty; however, those should be a part of the project structure and can be used for production use, which is out of the scope of this project.


## General preparation steps

Before proceeding to the script execution, the environment and certain accesses must be prepared in advance:
1. Virtual environment creation (Python>=3.10)
2. Install dependencies: pip install -r requirements.txt
3. Create a Pinecone account and create access tokens as per instruction [19]
4. Insert access token in .env file variable PINECONE_KEY
5. INDEX_NAME variable can remain the same

### Images preparation

Once the setup steps are finished, the database images along with the metadata should be downloaded [19] as zip, unarchived and placed as it is in the root directory – masters/data/raw – so that directory raw/images consists of images, raw/styles of .json files, and two .csv files (images.csv and styles.csv) remain in data/raw. Another subdirectory – raw/query – consists of various images that the users can use: product photos from the internet on white background, own pictures or photos of models/celebrities. This directory is pre-populated; however, any photo can be inserted for tests with the respect to gender.

### Model execution

After the virtual environment is created, dependencies are installed, Pinecone access token is obtained, and images are loaded, we can proceed to the index creation and generation and upserting embeddings of the database images.

1. Run in terminal “python setup_create_embeddings_fron_db_images.py” to generate embeddings of the images. This command will overwire pre-computed embeddings saved 
in .json file at embeddings/database subdirectory.
2. Run in terminal “python setup_create_index_and_upsert_db_embeddings.py” to create index and upsert embeddings generated by the command above.
